# Диагностика зеркального CAM-проекта

**Русский** | [English](en/mirror-project-diagnostic.md)

Скрипт: [`NX_Mirror_Project_Diagnostic.py`](../scripts/NX_Mirror_Project_Diagnostic.py). Версия: **V1**.

## Изменения последней версии

**V1 · 13.11.2026** — первый диагностический выпуск для разработки отдельной зеркальной копии сборки с самостоятельными CAM-операциями и перенесёнными MCS.

Скрипт читает структуру открытого проекта, типы геометрических элементов, операции и доступные геометрические ссылки. Результат появляется в отдельном окне с кнопкой «Копировать всё».

**Это диагностика. Зеркалирование, клонирование компонентов, перенос MCS и привязок операций ещё не реализованы. Наличие отчёта не означает, что проект пригоден для автоматического зеркалирования.**

## Порядок работы

1. Откройте нужную верхнюю сборку CAM-проекта и сделайте её отображаемой деталью (**Display Part**). Если нужны данные всех компонентов, предварительно полностью загрузите их штатными средствами NX.
2. Запустите **Tools → Journal → Play** и выберите скрипт. В апдейтере он называется **«Диагностика зеркального CAM-проекта»**.
3. Дождитесь окна результата. Нажмите **«Копировать всё»** и передайте текст разработчику для анализа переноса привязок.
4. Закройте окно. Скрипт не сохраняет и не закрывает проект.

## Что считывается

- Уже загруженные прототипы компонентов, повторяющиеся вхождения и их положения по `Component.GetPosition` в контексте NX. Одинаковая деталь исследуется один раз, её вхождения перечисляются отдельно.
- Полнота загрузки, признак изменения, количество тел и распределение типов модельных элементов.
- Все операции и группы дерева геометрии: класс, имя, наличие траектории, признак зеркальной операции и геометрический родитель.
- Каталог обязательных параметров UF с типами; значения пространственных и ссылочных параметров, а также отдельных числовых параметров, найденных по геометрическому названию. Их значения **не преобразуются**. Системы координат, найденные по ссылкам, выводятся с началом и матрицей осей.
- Геометрия Part, Blank, Check, Cut Area, Trim, Wall, Drive; доступные границы, ссылки на их элементы и пользовательские начальные точки/точки предварительного сверления.
- Ошибки чтения и ограничения объёма. Неизвестные типы не трактуются по предположению; несовпадение числа элементов UF с возвращённым массивом отмечается как ошибка.

## Файлы и изменения

Результат формируется в памяти. Скрипт не создаёт PRT, INI, TXT, ZIP, журналы, временные файлы или папки; не выполняет загрузку дополнительных деталей, Save, SaveAs, Update, Generate, Undo и не создаёт/фиксирует builders. Буфер обмена изменяется только по нажатию «Копировать всё».

В тексте есть имена деталей, операций и координаты. Скрипт не запрашивает полные пути файлов; сообщения об ошибках самого NX могут содержать пути. Перед передачей можно просмотреть текст. Ничего автоматически не отправляется.

## Ограничения и проверка

- Диагностика рассчитана на Windows и запуск внутри NX / Designcenter. Для окна используется Win32, без внешних библиотек или `.dlx`.
- Неполностью загруженные детали помечаются и пропускаются. Скрипт не подгружает их сам.
- UF предоставляет только часть внутреннего представления CAM. Это не полный экспорт всех настроек, WAVE-связей, выражений, сборочных ограничений или FBM-данных. Недоступный вызов может означать неподдерживаемый тип объекта, а не повреждение проекта.
- Пределы: 500 деталей, 5000 вхождений, 3000 CAM-объектов на деталь, 10000 индексов на CAM-объект, 200 элементов на вложенный список. Все сокращения обозначаются в `limits` или полем `omitted`.
- Выполнены переносимые проверки обработки частично загруженных деталей, повторных компонентов, ошибок чтения и неполных массивов. **Запуск в NX 2606 и отображение окна на Windows пока не проверены.**
