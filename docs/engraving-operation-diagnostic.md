# Диагностика операции гравировки

**Русский** | [English](en/engraving-operation-diagnostic.md)

## Изменения последней версии

**V1 · 23.11.2026** — отдельный журнал для сбора настроек существующей PLANAR_MILL / PLANAR_PROFILE. Показывает текстовый отчёт с кнопками **«Сохранить JSON»** и **«Копировать всё»**. Данные нужны для разработки создания операции гравировки при запуске основного скрипта без выбранной операции. Само создание операции в этой версии ещё не добавлено.

Рабочий файл: [NX_Engraving_Operation_Diagnostic.cs](../scripts/NX_Engraving_Operation_Diagnostic.cs). Пункт апдейтера: **«Диагностика операции гравировки»**.

## Как получить отчёт

1. Настройте одну операцию гравировки так, как должны создаваться будущие операции. Подтвердите настройки кнопкой OK и закройте её редактор.
2. Выделите эту операцию в **Operation Navigator**. Она должна принадлежать рабочей CAM-детали. Наличие рассчитанной траектории не требуется.
3. Запустите диагностический журнал через **Tools → Journal → Play** или свою кнопку.
4. Нажмите **«Сохранить JSON»**, выберите папку и прикрепите полученный `.json` к сообщению. Либо нажмите **«Копировать всё»** для полного текста, включая невидимую часть отчёта.

Окно отчёта можно растягивать. Сохранение JSON выполняется только по нажатию кнопки; отмена выбора файла ничего не записывает. При выборе существующего файла Windows запрашивает замену. Автоматической отправки данных нет.

## Что считывается

- Имя, класс, единицы детали, версия NXOpen и значения Template Type / Template Subtype.
- Родительские цепочки Program Order, Machine Tool, Geometry и Machine Method, включая инструмент, MCS и Workpiece.
- Required / inherited UF-параметры операции и родительских групп. Для операции дополнительно проверяются публичные индексы из установленной NXOpen.UF; неприменимые индексы пропускаются. Для каждого применимого параметра записываются индекс, имя, тип, текущий статус Default / Inherited / Overridden, источник и значение.
- Доступные свойства редактора: подача, обороты, шаблон резания, уровни, припуски, допуски, ось инструмента, подводы, отводы, переходы и компенсация. Числовые параметры не округляются для показа.
- Источники геометрии, назначенные объекты, сохранённые границы и их элементы, тип Open / Closed, припуски, допуски и положение инструмента.
- UDE начала и конца операции, типы параметров и состояния необязательных параметров.

JSON имеет схему `nx-engraving-operation-diagnostic`, `schema_version: 1`. В `records` находятся записи `context`, `parent`, `parameter`, `setting`, `list`, `alias`, `geometry_provider`, `geometry_item`, `boundary_member`, `ude_parameter` и `error`. `problems` перечисляет недоступные чтения; `report` содержит тот же полный текст, что в окне. Числа и булевы значения сохраняют тип. Идентификаторы Tag относятся к исходной модели и не являются переносимыми ссылками для новой детали.

## Ограничения и проверка

Это диагностический снимок доступных API-данных, **не готовый шаблон для импорта** и не обещание получить каждую внутреннюю настройку NX. Неподдерживаемые типы, ошибки чтения и ограничения обхода помечаются `UNAVAILABLE` / `UNSUPPORTED`; `partial` становится `true`. Такой файл всё равно полезен — отправьте его целиком. Внутренние указатели не разыменовываются. Предпросмотр и редактор траектории исключены; произвольные методы объектов не вызываются. Предел обхода: 16 уровней и 20 000 узлов, достижение отмечается явно.

Журнал не вызывает Commit, не назначает параметры, не создаёт операции или кривые, не рассчитывает траекторию и не сохраняет PRT. Созданный для чтения редактор уничтожается в `finally`. Сравниваются набор операций, прямые родители, состав и считанные данные Part Boundaries и флаг IsModified; это не побайтовое сравнение всей модели. Непроверенный результат отмечается отдельно, автоматического отката нет.

Единственный файл — выбранный пользователем JSON; временные файлы, INI, журналы и архивы не создаются. Отчёт содержит имена объектов и настройки модели; передавайте его намеренно. При недоступном собственном окне используется стандартное окно NX Information, чей заголовок не задаётся журналом.

Исходник компилируется с библиотеками Designcenter 2606 для .NET Framework и .NET 10. Вне NX проверены типизированные читатели, числовая точность и Unicode JSON, длинные данные, неподдерживаемые типы и сбои чтения, циклические ссылки, запрет вызова методов записи и освобождение редактора при ошибке. Проверена структура Windows-диалога сохранения. Работа на реальной операции NX и интерактивное окно требуют проверки пользователем; NX при разработке не запускался.
