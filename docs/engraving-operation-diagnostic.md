## Изменения последней версии

**V1.01 · 23.11.2026** — в JSON добавлены точки предварительного сверления и начала резания, плоскости безопасности и нижнего предела, наследование границ и порядок событий UDE. Если отдельное чтение завершается ошибкой, журнал записывает причину и продолжает собирать доступные данные. В апдейтере выберите **«Диагностика операции гравировки»**. Постоянный файл — [NX_Engraving_Operation_Diagnostic.cs](../scripts/NX_Engraving_Operation_Diagnostic.cs).

## Как получить отчёт

1. Откройте рабочую CAM-деталь в **Manufacturing**. Подтвердите настройки эталонной **PLANAR_MILL** или **PLANAR_PROFILE** кнопкой **OK** и закройте редактор операции.
2. В **Operation Navigator** выделите только эту операцию. При выборе нескольких узлов журнал выдаёт сообщение об ошибке выбора.
3. Запустите диагностический журнал через **Tools → Journal → Play** или свою кнопку NX.
4. В окне отчёта нажмите **«Сохранить JSON»** и укажите файл с расширением `.json`. Кнопка **«Копировать всё»** копирует полный текст отчёта, включая строки за пределами окна.

## Что считывается

- Имя и класс операции, единицы рабочей детали, версия NXOpen, Template Type и Template Subtype.
- Родители в представлениях Program Order, Machine Tool, Geometry и Machine Method, включая инструмент, MCS и Workpiece.
- Параметры UF операции и родительских групп. Журнал читает списки required и inherited, а для операции проверяет также публичные индексы установленной NXOpen.UF. Для применимых параметров записываются индекс, имя, тип, статус Default / Inherited / Overridden, источник и значение. Для типов длины поле `units` содержит единицы детали. Для остальных типов оно равно `null`. Единицы подачи и оборотов ищите в связанных настройках редактора.
- Доступные свойства редактора, включая подачи и обороты, шаблон резания, уровни, припуски, допуски, ось инструмента, подводы, отводы, переходы и компенсацию.
- Точки предварительного сверления и начала области резания с координатами в абсолютной системе детали и доступными полями глубины. Для плоскостей журнал отдельно читает статус и режим использования. Начало и нормаль запрашиваются для заданных плоскостей, включая неактивные.
- Выбранные объекты и списки выбора, поставщики геометрии, локальные и унаследованные границы. В отчёте есть число границ, состав каждой, доступные типы Open / Closed и Tool Position, припуски и допуски.
- События начала и конца UDE в исходном порядке, включая события без параметров. Для параметров записываются тип, состояние и доступное значение.

## Как читать JSON

Схема — `nx-engraving-operation-diagnostic`, версия схемы — `1`. В массиве `records` находятся записи `context`, `parent`, `parameter`, `setting`, `list`, `alias`, `geometry_provider`, `geometry_item`, `boundaries`, `boundary_member`, `ude_set`, `ude`, `ude_parameter`, `verification` и `error`. Поле `report` содержит полный текст из окна.

Числа записываются с точностью для обратного чтения. Сохраняются `0`, `false`, пустая строка, пустой список и `null`. У UF-параметра флаги `value_available` и `source_available` независимы. При `partial: true` откройте `problems` для пути и причины пропуска. Записи `error` содержат тип исключения, сообщение, стек и код NX, если он доступен. Считанные разделы остаются в том же файле. Теги объектов относятся к исходной детали.

## Файлы и ограничения

Журнал работает в режиме чтения. Журнал не вызывает `Commit`, не рассчитывает траекторию и не сохраняет PRT. Редактор операции освобождается в `finally`. Запись `verification` содержит флаг IsModified до и после чтения и результат сравнения списка операций, непосредственных родителей и считанных Part Boundaries. Значение `null` означает, что сравнение выполнить не удалось. Проверка охватывает перечисленные данные модели.

Окно отчёта можно растягивать. Только кнопка **«Сохранить JSON»** записывает файл, в UTF-8 без BOM. При отмене окно возвращается к отчёту. При замене файла Windows запрашивает подтверждение. Журнал хранит прежние байты в памяти и при ошибке записи пытается восстановить их. Если восстановление тоже завершилось ошибкой, окно показывает обе причины. Временные файлы, INI и архивы не создаются. При сбое собственного окна полный текст доступен в NX Information.

Внутренние указатели, предпросмотр и редактор траектории исключены из обхода. Пределы обхода свойств — 16 уровней и 20 000 узлов. Недоступные данные отмечаются в отчёте. Автотесты используют синтетические операции и проверяют типы значений, наследование, геометрию, обработку ошибок и запись файла. Полный исходник V1.01 с библиотеками NXOpen 2412 прошёл компиляцию для .NET Framework 4.8 и с ограниченным набором сборок .NET 10 для Windows, используемым при проверке журналов. Проверка на эталонной операции и проверка диалога в Designcenter 2606 выполняются в NX.
