# Апдейтер V1.18

**Русский** | [English](en/updater.md)

Скрипт: [NX_Update_Scripts.py](../scripts/NX_Update_Scripts.py). [Все скрипты](../README.md#скрипты).

Устанавливает новые журналы и обновляет выбранные рабочие файлы, сохраняя их постоянные пути.

Рабочая папка по умолчанию — `C:\ProgramData\NX_SCRIPTS`. Если путь уже задан в INI, используется сохранённое значение. Чтобы перенести существующую установку в другую папку, переместите скрипты вместе с INI, измените «Рабочую папку» в апдейтере и пути команд NX.

## Возможности

- Два источника: публичный каталог GitHub и выбранная пользователем папка.
- Поиск рабочих `.py`, `.cs` и `.vb`; отдельно включаемый поиск в подпапках рабочей папки и источника.
- Таблица с названием, рабочим файлом, установленной и доступной версиями, состоянием. При выборе строки внизу показываются пути, описание и причина ограничения.
- Ячейка «Доступно» выделяется зелёным `#00CD86` (RGB 0, 205, 134), если версия источника новее установленной. Подсветка сохраняется при выборе и сортировке; после обновления и повторной проверки исчезает. Новые скрипты без установленной копии, неизвестные и одинаковые версии не подсвечиваются.
- Сортировка по нажатию на заголовок любой колонки: повторное нажатие меняет направление, стрелка показывает порядок. Версии сравниваются численно; галочки и выделенная строка сохраняются.
- Ручные галочки, «Выбрать обновления», «Выбрать новые скрипты» и «Снять все».
- Двойной клик по строке ставит или снимает галочку, в том числе в колонках версий и состояния. Квадратик также доступен для обычного нажатия; недоступные строки остаются защищены от выбора.
- Проверка внутренней версии и контрольной суммы, обнаружение местных правок и неоднозначных копий, запрет понижения версии.
- Установка новых файлов с постоянными именами и обновление существующих по их рабочим путям.
- Первоначальная установка примеров INI из GitHub с сохранением уже существующих настроек.
- Отложенное самообновление из GitHub после закрытия окна; в режиме папки работающий апдейтер пропускается.
- Сохранение настроек кнопкой «Проверить» и отдельная кнопка «Перечитать INI».
- Отмена проверки закрытием окна, защита от второго окна в текущем сеансе Windows, откат при обычной ошибке записи.

## Как пользоваться

1. Запустите журнал из рабочей папки через NX Journal → Play.
2. Проверьте поля «Рабочая папка» и «Источник». Для GitHub укажите Raw-адрес manifest ниже; для режима папки выберите её через «Обзор…».
3. Нажмите «Проверить». Настройки самого апдейтера сохранятся в INI; рабочие скрипты на этом этапе не заменяются.
4. При необходимости отсортируйте таблицу нажатием на заголовок колонки. Посмотрите состояния и подробности нужных строк, отметьте выбранные скрипты галочкой или двойным кликом по строке.
5. Нажмите «Применить выбранное», прочитайте подтверждение и дождитесь результата.
6. Повторите «Проверить»: у успешно установленных файлов ожидается «Установлена эта версия».

| Состояние | Что означает |
| --- | --- |
| Новый скрипт — установка | Файла ещё нет; установку нужно выбрать. |
| Новая версия | Доступно обновление; проверенная рабочая копия без местных правок может быть отмечена автоматически. |
| Происхождение не подтверждено / местные правки / нет версии | Требуется индивидуальный ручной выбор и проверка заменяемого файла. |
| Та же версия, другой код | Номера версий совпадают, содержимое различается; выбор только вручную. |
| Установлена эта версия | Содержимое совпадает с каталогом; повторная установка не нужна. |
| На ПК более новая версия | Понижение заблокировано. |
| Несколько рабочих файлов одного скрипта | Нужно оставить один рабочий путь; апдейтер не выбирает копию сам. |
| Нет в каталоге GitHub | Локальный файл остаётся на месте и не обновляется из каталога. |

Для первого теста в NX используйте [пошаговую проверку](installation.md#проверка-апдейтера-в-nx). Если установлен `NX_Update_Script_Buttons.py` V1.12 или старше, сначала выполните [однократный переход на новое имя](installation.md#переход-со-старого-имени-апдейтера).

Для запуска с ленты создайте [кнопку NX](installation.md#кнопки) один раз и укажите постоянный путь к `NX_Update_Scripts.py`. Последующие обновления меняют содержимое файла; действие кнопки сохраняется.

## Источник GitHub

Постоянный каталог: [Raw manifest](https://raw.githubusercontent.com/TonyFoxxxx/NXOpen-SCRIPTS/main/manifest.json).

Базовый адрес файлов: `https://raw.githubusercontent.com/TonyFoxxxx/NXOpen-SCRIPTS/main/`. Например, [карта наладки](https://raw.githubusercontent.com/TonyFoxxxx/NXOpen-SCRIPTS/main/scripts/NX_Setup_Prototype.py). Обычные адреса `github.com/.../blob/...` возвращают HTML и для скачивания исходника апдейтером не используются.

## Проверка

1. Прочитать INI, проверить рабочую папку и выбранный источник.
2. Скачать один manifest по HTTPS. Исходники `.py`/`.cs` на этом этапе не скачиваются.
3. Проверить схему 1, обязательные поля, уникальность записей, версии и допустимые пути.
4. Прочитать внутренние версии локальных файлов и проверить служебную отметку, если она есть.
5. Показать новые скрипты и обновления в существующем окне выбора.

Версии сравниваются по числовым компонентам: `V1.09 < V1.10`. Основной номер автоматически не меняется. Новые файлы, файлы без подтверждённого происхождения, местные правки и различающийся код той же версии не выбираются автоматически. Версия на ПК новее каталога — обновление запрещено. Две рабочие копии одного семейства блокируют неоднозначное обновление.

## Источник-папка

Можно устанавливать отсутствующие и обновлять существующие журналы из локальной или сетевой папки. Кандидаты сопоставляются по семейству имени и внутренней версии; учитываются исключения INI и настройка поиска в подпапках.

В этом режиме копируются только скрипты: примеры INI и другие сопутствующие файлы не устанавливаются. Самообновления работающего апдейтера нет. При недоступности GitHub переключение на папку автоматически не выполняется.

## Установка и обновление

После выбора скачиваются только нужные исходники и необходимые начальные примеры. До изменения рабочих файлов проверяются все загрузки: SHA-256, размер, внутренняя версия, комментарий в шапке и константа `SCRIPT_VERSION`. Для Python также проверяется синтаксис без исполнения кода.

При новой установке создаётся файл с постоянным именем в рабочей папке. Отсутствующий INI создаётся из примера вместе с отсутствующим скриптом; существующий INI сохраняется. INI и Excel нумератора также устанавливаются рядом с его скриптом. При обновлении нумератора существующая пара в новой папке сохраняется; при её отсутствии переносится прежняя пара из `C:\ProgramData\3_NX_DATA`. Пустой реестр скачивается только для первой установки без прежней истории. Потерянная история и конфликтующие реестры требуют восстановления, а не обнуления.

Обычное обновление заменяет выбранный скрипт по существующему пути. Для нумератора V1.04 также выполняется описанный перенос отсутствующих файлов. Существующие пользовательские INI, модели, реестры и кнопки сохраняются. Скачанный скрипт во время установки не исполняется. Комментарий `NX_UPDATER_INSTALLED_V1` в конце установленного файла хранит контрольную сумму исходника и помогает обнаружить местные правки.

## Запись и сбои

Перед записью ещё раз проверяются локальные контрольные суммы. На Windows существующие файлы защищены от сторонней записи и переименования во время подготовки. Непосредственно перед атомарной заменой защитный дескриптор текущего файла закрывается; остальные файлы остаются защищены до своей очереди. Это устраняет ошибку `WinError 5` в V1.09. Изменения, обнаруженные при повторной проверке, отменяют операцию. Не редактируйте рабочие файлы параллельно с установкой: между закрытием дескриптора и заменой остаётся короткий интервал.

Новая версия записывается в проверенный `.nxupdater-….pending` рядом с назначением, затем заменяет файл целиком. Промежуточное имя не имеет расширения журнала и не запускается. При обычной ошибке записи выполняется откат из памяти; если откат не удалось завершить, сообщение перечисляет проблемные пути. Постоянные резервные копии и логи апдейтер не создаёт.

Атомарность относится к **одному файлу**, а не ко всей выбранной группе. При аварии NX/Windows или отключении питания часть группы может быть обновлена, часть остаться прежней. После запуска выполните новую проверку. Остатки `.pending` от завершённых процессов удаляются при следующем запуске. Это не замена отдельной резервной копии важных пользовательских данных.

## Переход на V1.18

1. В старом апдейтере нажмите «Проверить», выберите апдейтер V1.18 и примените обновление. Другие скрипты до этого шага будут недоступны.
2. После закрытия окна запустите апдейтер заново. Укажите свою рабочую папку, например `C:\ProgramData\2. NX_Scripts`, и нажмите «Проверить».
3. Выберите нумератор V1.04 и примените обновление. Закройте его Excel-реестр и завершите другие запуски нумератора перед переносом.
4. В рабочей папке появятся скрипт, `NX_Numbering_Settings_v1.0.ini` и реестр из `RegistryFile`. Прежние настройки и история сохраняются; при первой установке свой диапазон нужно задать в INI.
5. Если скрипт перенесён, один раз измените путь его кнопки NX. При дальнейших обновлениях путь остаётся прежним.

Если рабочие файлы уже перенесены, они имеют приоритет. При отсутствии прежней пары или различающихся реестрах апдейтер остановится с указанием пути. Восстановите свои данные; пустой шаблон не заменяет историю номеров. Если файлы отсутствуют при уже актуальной версии скрипта, строка восстановления доступна для ручного выбора.

## Самообновление

При выборе запущенного файла апдейтера его загрузка проверяется и остаётся в памяти. Сначала обновляются остальные выбранные файлы. Затем закрывается окно, завершаются рабочие потоки и только после этого основной поток заменяет `.py`. Новая редакция исполняется при следующем запуске. Если старый процесс завершится до замены, старая версия останется на месте.

Запущенный Python-код уже загружен в память; новая версия не импортируется поверх работающей. Повторное окно апдейтера блокируется в текущем сеансе Windows. С V1.13 самообновление работает под постоянным именем `NX_Update_Scripts.py`. Переход с прежнего имени выполняется вручную по [инструкции](installation.md#переход-со-старого-имени-апдейтера).

## Формат manifest

```json
{
  "schema_version": 1,
  "min_updater_version": "V1.18",
  "scripts": [
    {
      "id": "NX_Setup_Prototype",
      "name": "Карта наладки",
      "file": "NX_Setup_Prototype.py",
      "version": "V2.37",
      "path": "scripts/NX_Setup_Prototype.py",
      "sha256": "<64 строчных шестнадцатеричных знака>",
      "description": "Карта наладки с видами, инструментами и Zmin.",
      "config": {
        "path": "config/NX_Setup_Prototype.example.ini",
        "file": "NX_Setup_Prototype.ini",
        "location": "script",
        "sha256": "<64 строчных шестнадцатеричных знака>"
      }
    }
  ]
}
```

Это пример полей, не готовый manifest: реальные контрольные суммы рассчитываются инструментом публикации. `id` равен имени файла без расширения; он постоянный. `config` отсутствует, если INI нет. `location=script` означает папку установленного журнала. С V1.18 значение `numbering_data` также означает папку установленного журнала, но включает специальную обработку настроек и истории нумератора и один `install_files` для начального XLSX. Минимальная версия V1.18 предотвращает установку нового нумератора старыми апдейтерами в прежнюю папку данных.

Новые журналы с обычным INI добавляются в каталог без изменения апдейтера. Для новых типов зависимостей или дополнительных каталогов установки потребуется расширение формата и поддержка в апдейтере. Неизвестная схема блокируется. Если повышен `min_updater_version`, старый апдейтер разрешает сначала обновить себя, а остальные записи блокирует.

## Доверие и ограничения

Используется только Raw HTTPS этого репозитория и ветки `main`, включая проверку перенаправлений. В manifest не допускаются внешние URL, обход каталогов, абсолютные пути или произвольные команды установки. TLS-проверка сертификатов включена; токены и пароли для публичного каталога не нужны.

В V1.15 при `CERTIFICATE_VERIFY_FAILED` встроенного Python NX запрос повторяется через WinHTTP: сертификат проверяет Windows, используются её настройки прокси и TLS 1.2. Перенаправления в резервном запросе запрещены; ограничения размера, проверка полноты и SHA-256 сохраняются. Данные загружаются в память без новых служебных файлов. Ошибка `WinHttpSetOption(TLS): 12018`, обнаруженная в V1.14, исправлена.

Если Windows также отклоняет сертификат, ошибка содержит её код и пояснение. Проверьте дату и открытие адреса manifest в браузере этого ПК; передайте ошибку администратору для проверки доверенных сертификатов и корпоративного прокси или антивируса. Апдейтер сам не устанавливает сертификаты и не меняет системные настройки. Если прежняя версия уже не может скачать каталог, замените `NX_Update_Scripts.py` вручную, сохранив существующий INI, и запустите апдейтер снова.

SHA-256 выявляет повреждение или несовпадение файлов с каталогом, но не является цифровой подписью автора. Источником доверия остаётся доступ к репозиторию. Смена `main` между проверкой и скачиванием может дать несовпадение SHA-256: операция отменится, нужно повторить проверку. Поэтому исходники и manifest публикуются одним коммитом.

Доступ к интернету, доверенные сертификаты Windows/Python и права записи в рабочую папку необходимы. Отключать TLS-проверку для обхода корпоративного прокси нельзя. Сборка C# и выполнение NXOpen в апдейтере не проверяются; изменения журналов нужно проверять в целевой NX.
