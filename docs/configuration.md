# Настройки и данные пользователя

**Русский** | [English](en/configuration.md)

Публичные примеры лежат в `config/`. Рабочее имя получается удалением `.example`: например, `NX_Postprocess_To_Machine.example.ini` → `NX_Postprocess_To_Machine.ini`. Сохраняйте в UTF-8. Существующий INI не заменяйте целиком при обновлении; новые параметры при необходимости переносите вручную.

## Карта наладки

`NX_Setup_Prototype.ini` находится рядом с `.py`:

```ini
[SetupCard]
programmer=
```

Впишите фамилию и инициалы после `=`. Если значение не задано, графа остаётся пустой и может быть заполнена в карте. Возможности создания и редактирования документа описаны в [руководстве карты наладки](setup-card.md).

## Zmin в именах операций

`NX_Operation_Zmin.py` не использует INI. Выбор операций, системы координат и траектории читаются из открытого CAM-проекта. Условия расчёта для 4 осей и порядок запуска описаны в [zmin.md](zmin.md).

## Постпроцессирование

`NX_Postprocess_To_Machine.ini` находится рядом с `.cs`. В окне выбора поста нажмите «Пути к постпроцессорам», добавьте запись или выберите существующую, задайте название и выберите файлы TCL/DEF. Одноимённый DEF рядом с выбранным TCL подставляется автоматически; иначе укажите его вручную. Нажмите «Сохранить», чтобы записать настройки и обновить список постов. «Отмена» ничего не записывает, а «Убрать» удаляет только запись из INI, сохраняя файлы поста.

Редактор сохраняет другие разделы и параметры, комментарии, кодировку и окончания строк существующего INI. Если INI отсутствует, первое сохранение создаёт его рядом со скриптом с `PostList=auto`; нужны права записи. Настройки также можно изменить вручную в `[Post …]`. Для обработки по привязкам в этой же секции доступны `WorkOffsetProfile=Auto` (либо `ISO_G28` / `ISO_G53`) и необязательный `WorkOffsetG53Z`. Последний задаёт подтверждённую машинную высоту исходного отвода G53, а не генерирует движение. Ограничения и порядок настройки — в [руководстве постпроцессирования](postprocess.md#профиль-конкретного-поста). Без новых ключей действует Auto.

Общие папки станков настраиваются через **«Папки со станками…»** в окне «Куда вывести УП?». «Добавить…» выбирает новую локальную или сетевую папку, «Обзор…» меняет путь выбранной записи; путь также можно вставить вручную. Изменения записываются в `[MachineRoots]` только после «Сохранить», затем список кнопок обновляется сразу. «Отмена» ничего не записывает, «Убрать» удаляет только запись. Остальные настройки, комментарии и кодировка INI сохраняются.

Автоматический список включает непосредственные подпапки с названиями из цифр, например `01`, `02`, `15`. Несколько корней поддерживаются. Отдельные папки с произвольными именами задаются вручную в `[Machines]` и продолжают отображаться вместе с автоматическим списком. После сохранения настроек выберите станок заново. [Порядок настройки через интерфейс](postprocess.md#папки-со-станками).

Пример `C:\CNC_Example` вымышленный. Постпроцессоры и станочные настройки не поставляются.

`[Settings] PostList=auto` добавляет посты NX; `DefaultExtension` задаёт расширение по умолчанию. После правок используйте «Обновить» в меню скрипта. Последний выбор сохраняется самим журналом в `%LOCALAPPDATA%\NX_Postprocess_To_Machine\LastChoice.ini`; апдейтер к этому файлу не обращается.

## ЕСКД

`NX_ESKD_Settings.ini` находится рядом с `.cs`. `[TitleBlock]` содержит организацию и подписи, `[Defaults]` — материал, `[TechnicalRequirements]` и `[SurfaceRoughness]` — параметры оформления. Технические требования из примера обязательно проверьте для своей детали.

Сам журнал сохраняет последний успешно применённый ввод в `[LastUsed]`; это штатное поведение ЕСКД. Апдейтер сохраняет INI целиком. Кнопка чтения базовых настроек позволяет заново взять значения из основных секций.

### Внешний шрифт

Рабочее семейство — `NX_ESKD_GOST_A_Italic_v111`. Поддерживается также прежний совместимый файл `NX_ESKD_GOST_A_Italic_v110.ttf`: журнал исправляет его метаданные в памяти и устанавливает отдельную копию `v111`, сохраняя исходный файл. Контуры, ширины символов, подсказки растеризации и таблица символов остаются прежними. Уже исправленная `v111` используется повторно.

**Файл шрифта в комплект не входит**; нужна отдельная разрешённая копия. Исправление метаданных в исходнике не содержит контуров символов и не позволяет создать шрифт без исходного файла. Другие GOST-шрифты автоматически не подставляются.

Скрипт ищет файлы обоих семейств (также варианты `_1` … `_99`) рядом с `.cs`, в `UGII_STANDARD_FONT_DIR`, пользовательских каталогах шрифтов Windows/NX и `%WINDIR%\Fonts`.

| Редакция | Размер, байт | CRC32 | SHA-256 |
| --- | --- | --- | --- |
| `v110` — исходная | 57 764 | `582A8BB4` | `648fa9e071903291a0e707312aa44f1f4638309440087363ff752989eb9e0c7b` |
| `v111` — исправленная | 57 764 | `4DD73259` | `373668d649781dc756f7a623f3e411cb4532f0d51e243e583f4a65fffbee368b` |

Перед установкой проверяются размер, CRC32 и SHA-256; после подключения — таблицы выбранного Windows шрифта. Новое внутреннее имя исключает совпадение со старым семейством в кэше NX. Проверки совместимости не предоставляют право на распространение шрифта.

Установленная совместимая копия может находиться в `%LOCALAPPDATA%\Microsoft\Windows\Fonts` или `%LOCALAPPDATA%\Siemens\NX_ESKD\Fonts`. Исправленный файл устанавливается тем же механизмом; действующая настройка `UGII_STANDARD_FONT_DIR` сохраняется. Репозиторий и апдейтер не скачивают сам шрифт. Если совместимого файла нет, журнал покажет сообщение и не выполнит оформление. См. [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md).

После обновления примените ЕСКД к чертежу и повторите экспорт PDF. Если NX попросит перезапуск, сохраните работу, перезапустите NX и повторите применение ЕСКД. Вручную менять INI или удалять старые шрифты не требуется.

## Нумерация папок программ

С V1.04 INI лежит рядом с `NX_Number_Program_Folders.cs` в выбранной рабочей папке. Например:

```text
C:\ProgramData\2. NX_Scripts\NX_Numbering_Settings_v1.0.ini
```

`Prefix`, `StartNumber` и `EndNumber` задают префикс и диапазон. Диапазон `1–1000` в примере иллюстративный: перед первым запуском назначьте свой непересекающийся диапазон с учётом уже выданных номеров.

`RegistryFile` указывает на XLSX-реестр. Относительное имя считается от папки INI; абсолютный путь также поддерживается. Реестр — история выдачи номеров, а не обновляемая настройка. Excel для чтения реестра этим журналом не требуется.

Апдейтер V1.19 обновляет код даже при отсутствии INI/Excel. Затем переносит подходящую прежнюю пару из `C:\ProgramData\3_NX_DATA` или предлагает [отдельную настройку](updater.md#настройка-данных-нумерации). Ошибка переноса не отменяет обновление скрипта. Прежние файлы остаются на месте.

Выберите существующий `.xlsx`; он используется по своему пути без изменения содержимого. При отсутствии INI введите свой Prefix, StartNumber и EndNumber. При наличии корректного INI диапазон и комментарии сохраняются, меняется только RegistryFile. Пустой шаблон загружается в папку скрипта только по явному выбору «Новая нумерация» с подтверждением и своим диапазоном. При потерянной истории используйте [восстановление из NX](number-program-folders.md#recovery).

«Отложить» сохраняет обновлённый скрипт без настройки. При актуальной версии с недостающими данными строку «Нужна настройка данных нумерации — выбор вручную» можно выбрать после повторной проверки. Ошибки существующего INI исправляются вручную. Закройте Excel и другие запуски нумератора перед переносом или подключением реестра.

Суффикс `v1.0` входит в постоянные имена INI и шаблона XLSX; при установке его нужно сохранить.

## Апдейтер

`NX_Update_Scripts.ini` находится рядом с `.py`:

```ini
[Paths]
working_folder=C:\ProgramData\NX_SCRIPTS
update_folder=

[Source]
type=github
manifest_url=https://raw.githubusercontent.com/TonyFoxxxx/NXOpen-SCRIPTS/main/manifest.json

[Options]
search_update_subfolders=yes
search_working_subfolders=no
exclude_files=NX_Update_Scripts*.py
```

При переходе со старого имени переименуйте рабочий INI по [инструкции](installation.md#переход-со-старого-имени-апдейтера), сохранив содержимое. Если основной INI отсутствует, апдейтер также читает `NX_Update_Script_Buttons.ini` и сохраняет настройки в этом же файле. При наличии обоих приоритет у `NX_Update_Scripts.ini`.

GitHub — режим по умолчанию, включая старый INI без `[Source]`. `search_update_subfolders` относится только к источнику-папке. Старое исключение апдейтера действует в режиме `folder`; GitHub включает его отдельно для безопасного самообновления.

Кнопка «Проверить» сохраняет выбранные параметры **самого апдейтера**. Посторонние секции/параметры сохраняются, кроме устаревшего динамического `[Scripts]`; оформление и комментарии INI могут быть перезаписаны парсером. Другие пользовательские INI эта кнопка не меняет.

Для ручного офлайн-источника укажите `type=folder` и `update_folder`. Можно выбрать папку через «Обзор…» в интерфейсе. При ошибке GitHub переключения на папку не происходит. В режиме папки устанавливаются и обновляются только скрипты, без загрузки example INI и без самообновления.
