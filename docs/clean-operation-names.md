# Очистка названий операций

**Русский** | [English](en/clean-operation-names.md)

Файл: [`NX_Clean_Operation_Names.cs`](../scripts/NX_Clean_Operation_Names.cs). Версия: **V1**.

## Изменения последней версии

**V1 · 08.11.2026**

- Новый отдельный журнал очищает служебные хвосты копирования и создания экземпляров у всех CAM-операций рабочей детали.
- Повторы получают `_1`, `_2` и далее по порядку программ; первый свободный вариант остаётся без номера. Номер ставится перед Z.
- Существующий суффикс Z сохраняется точно, включая знак, десятичные знаки и завершающие нули. Глубина не вычисляется.
- Предусмотрены проверка совпадений со всеми CAM-группами, одна общая отмена и откат при ошибке переименования.

## Назначение

Журнал убирает цепочки `_COPY`, `_INSTANCE`, `_INSTANT`, `_DUPLICATE`, `_КОПИЯ`, `_ЭКЗЕМПЛЯР` и их номера, например `_COPY2` или `_INSTANCE_1`. Регистр служебных слов не имеет значения. Удаляется только служебный хвост, а не совпадение внутри содержательного названия: `COPY_MILL` и `MILL_COPY_FINISH` сохраняются.

Конечные целые числа после подчёркивания считаются прежними номерами повторов и назначаются заново. Поэтому одиночная операция `KARMAN_CHERN_DORAB_2` станет `KARMAN_CHERN_DORAB`; если таких операций несколько, будут `KARMAN_CHERN_DORAB`, `KARMAN_CHERN_DORAB_1`, `KARMAN_CHERN_DORAB_2` и далее. Это правило действует и на вручную введённый конечный номер: его происхождение определить невозможно. Числа в `D11`, `3D`, `14H7`, `R1` и внутри `STEP_2_FINISH` сохраняются. Слова `NEW`, `MIRROR` и произвольные части названия не удаляются.

Z может находиться перед хвостом копирования или после него. Он переносится в конец без изменения текста. При совпадениях номер ставится перед Z; имена с разными суффиксами Z считаются разными. Суффикс распознаётся как `Z` с числом, например `Z-33.8046`, `Z0`, `Z+2.500`, `Z-1,25`. Текст, не похожий на числовой Z, остаётся частью названия.

Примеры ниже показывают обработку каждой группы сверху вниз:

| До | После |
| --- | --- |
| `PROFILE_3D` | `PROFILE_3D` |
| `PROFILE_3D_INSTANCE` | `PROFILE_3D_1` |
| `PROFILE_3D_INSTANCE_1` | `PROFILE_3D_2` |
| `PROFILE_3D_INSTANCE_INSTANCE` | `PROFILE_3D_3` |
| `PROFILE_3D_COPY` | `PROFILE_3D_4` |
| `PLSK_CHIST_Z0` | `PLSK_CHIST_Z0` |
| `PLSK_CHIST_Z0_COPY` | `PLSK_CHIST_1_Z0` |
| `PREDV_D11_Z-33.8046` | `PREDV_D11_Z-33.8046` |
| `PREDV_D11_1_Z-33.8046_COPY` | `PREDV_D11_1_Z-33.8046` |

## Запуск

1. В апдейтере нажмите **«Проверить»**, отметьте **«Очистка названий операций»** и нажмите **«Применить выбранное»**.
2. Откройте нужную рабочую деталь с CAM-проектом.
3. Запустите `NX_Clean_Operation_Names.cs` через **Инструменты → Журнал → Воспроизвести** или свою кнопку.
4. Очистка выполняется сразу для всей рабочей детали. Выделять операции или папки не нужно; выделение не ограничивает область работы.
5. В результате показаны количество переименованных операций и первые десять изменений. Отмена всего запуска — **Ctrl+Z**.

Нумерация идёт по дереву **«Порядок программ»**, включая вложенные папки, независимо от текущего вида навигатора. Операции, отсутствующие в этом дереве, обрабатываются после него в порядке CAM-коллекции. Рассчитанные, нерассчитанные операции и экземпляры обрабатываются одинаково.

## Совпадения и повторный запуск

Уникальность проверяется без учёта регистра по всей рабочей детали. Занятые имена папок, инструментов, геометрии и методов пропускаются; из-за этого в нумерации возможны пропуски. Например, при наличии инструмента `MILL` первая операция получит `MILL_1`.

При неизменных операциях, порядке дерева и именах CAM-групп повторный запуск не меняет уже очищенные имена и не создаёт лишнюю отметку отмены. После удаления или перестановки операций номера могут измениться согласно новому порядку.

## Изменения проекта и ограничения

- Изменяются только имена операций. Операции не пересоздаются; инструменты, папки, геометрия, методы и траектории не удаляются и не пересчитываются.
- Скрипт не создаёт файлов, логов, INI или атрибутов и не сохраняет PRT автоматически. Сохраните деталь обычным способом, если хотите закрепить результат.
- Для перестановок используются временные имена объектов в памяти NX. После успешного запуска остаются только окончательные имена. Это не временные файлы.
- При ошибке назначения или усечении имени со стороны NX выполняется откат всего запуска и проверяется восстановление исходных имён. Если NX не смог выполнить отмену, окно сообщает об этом явно.
- Ошибка обновления навигатора не отменяет успешное переименование: обновите дерево вручную.
- Это отдельный журнал. Скрипты Zmin, карты наладки, постпроцессирования и переименования выделенных операций не изменены.

## Проверки

Проверены примеры имён, точное сохранение Z, порядок обхода, конфликты с CAM-группами, повторный запуск, одиночная отмена, принудительные ошибки и неполный откат на исполняемой модели NX API. Дополнительно проверено 5000 имён со смешанными цепочками суффиксов. Исходник скомпилирован с установленными библиотеками **Designcenter 2606**; каталог, установка через апдейтер и регрессионные тесты проверены отдельно. Запуск этой версии внутри NX на производственной детали ещё не выполнен.

В общей локальной проверке пройдены 287 из 288 тестов с учётом повторной проверки ЕСКД в подходящей кодировке. Прежний тест нумератора папок завершился с кодом 5 без диагностики; его исходник, тест и XLSX-шаблон не изменены. Проверки нового журнала и апдейтера пройдены.
