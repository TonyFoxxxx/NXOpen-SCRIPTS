# Нумерация папок программ

**Русский** | [English](en/number-program-folders.md)

Скрипт: [NX_Number_Program_Folders.cs](../scripts/NX_Number_Program_Folders.cs). [Все скрипты](../README.md#скрипты).

Присваивает программным папкам номера из заданного диапазона и ведёт историю выдачи в XLSX.

## Изменения последней версии

**V1.05 · 21.10.2026.** После удаления папки скрипт использует её номер для восстановления порядка внутри этого проекта. Например, после удаления `O1689` папка `O1690` становится `O1689`. Свободный номер в конце остаётся в резерве этого проекта. Апдейтер V1.19 обновляет код даже без INI/XLSX и предлагает настройку отдельно.

## Возможности

- Обходит всё дерево Program Order, включая вложенные ветки. Обрабатывает папки, имя которых начинается с латинской заглавной O; выделение пользователя не задаёт область работы.
- Назначает номера по порядку дерева с префиксом и диапазоном из INI.
- При вставке, удалении или перестановке папок перераспределяет номера текущего проекта по порядку дерева.
- При повторном запуске без изменений сохраняет уже назначенные номера.
- Сопоставляет папки с реестром по служебным атрибутам и пути проекта. Копирование папки с атрибутами не считается выдачей того же номера второй папке.
- Проверяет конфликты имён со всеми CAM-объектами и наличие свободных номеров.
- Хранит в реестре номер, проект, путь, дату, прежнее имя, состояние и служебный идентификатор.
- Резервирует новые номера до изменения NX. Подтверждённые номера удалённых папок доступны повторно только этому проекту; неиспользованный хвост отмечается в примечании как резерв проекта. Номера чужих проектов, отменённых и неподтверждённых выдач остаются занятыми.
- Блокирует одновременную работу с реестром и проверяет, не изменился ли XLSX другой программой.
- При ошибке пытается отменить изменения в NX и обновить состояния записей. Зарезервированные номера не возвращаются в свободный диапазон.
- Читает и записывает XLSX без установленного Microsoft Excel.

## Как пользоваться

1. Сохраните CAM-проект в PRT и проверьте порядок папок Program Order.
2. Для первой установки настройте свой диапазон и путь к реестру в INI. Если номера уже выдавались, используйте существующий рабочий реестр.
3. Запустите журнал. Отдельного окна выбора папок нет.
4. Проверьте сообщение о новых и изменённых номерах, затем сохраните PRT.

Не отменяйте нумерацию только через Undo NX в расчёте вернуть номера в общий пул: файловая история XLSX изменяется отдельно от модели.

## Настройки и файлы

- С V1.04 INI `NX_Numbering_Settings_v1.0.ini` находится рядом с `NX_Number_Program_Folders.cs`, независимо от имени рабочей папки. Например: `C:\ProgramData\2. NX_Scripts`.
- Апдейтер V1.19 сначала устанавливает/обновляет код. Затем переносит подходящую прежнюю пару из `C:\ProgramData\3_NX_DATA` или предлагает подключить существующий реестр, настроить новую нумерацию либо отложить настройку. INI и новый XLSX создаются рядом со скриптом; существующий выбранный XLSX используется по своему пути. Подробнее: [настройки](configuration.md#нумерация-папок-программ).
- `Prefix`, `StartNumber` и `EndNumber` задают формат и диапазон; `RegistryFile` — существующий XLSX.
- Рядом с реестром текущая реализация создаёт файл блокировки `.lock` и предыдущую версию `.bak`. При записи используется `.tmp`, который удаляется после замены.
- В папки CAM записываются служебные атрибуты связи с реестром. PRT автоматически не сохраняется.

Отсутствующий или несовместимый реестр блокирует работу. Пустой шаблон подходит только для первой установки. Подробнее: [настройки нумерации](configuration.md#нумерация-папок-программ).

## Удаление папок и резерв проекта

На каждом запуске скрипт сравнивает дерево с XLSX. Для восстановления порядка использует только подтверждённые записи с тем же путём PRT и текущим префиксом, если их служебный ID больше не встречается в дереве и имя не занято другим CAM-объектом. Папка с сохранённой отметкой, вручную переименованная без `O`, не считается удалённой.

| До удаления | После удаления O1689 и запуска |
| --- | --- |
| O1686, O1687, O1688, O1689, O1690 | O1686, O1687, O1688, O1689 |

Запись `O1690` остаётся в XLSX за этим проектом и используется при следующем добавлении подходящей папки. ID записи переносится вместе с номером. Состояние строки остаётся `Присвоен`, резерв обозначается в примечании; новый формат книги не нужен. Записи других проектов не изменяются. Скрипт устраняет пропуски в доступных номерах своего проекта; занятые другими проектами/объектами и отменённые номера не присваиваются.

## Восстановление из NX

Кнопка «Восстановление из NX…» в настройке апдейтера открывает эту инструкцию. Сам апдейтер не восстанавливает историю и не запускает скачанный код.

1. Если сохранился заполненный или более старый Excel, используйте его. Скопируйте [журнал восстановления V1](../tools/NX_Recover_Numbering_Register.py) рядом с INI нумератора под именем `NX_Recover_Numbering_Register.py`.
2. Если Excel полностью утрачен, скачайте [пустую книгу](../templates/NX_Numbering_Register_v1.0.xlsx) в папку скрипта **только как основу для восстановления**, не заменяя существующий файл. В апдейтере подключите её как существующий реестр. При отсутствии INI укажите прежний выделенный диапазон. Обычную нумерацию пока не запускайте.
3. Откройте сохранённый исходный CAM-проект с отметками нумерации. Закройте Excel и другие запуски нумератора. Запустите журнал восстановления через Alt+F8, проверьте список и подтвердите добавление строк.
4. Повторите для всех проектов с потерянной историей перед выдачей новых номеров. Журнал добавляет отсутствующие записи, сохраняет прежние строки и не изменяет NX. При конфликте останавливается.

Восстанавливаются только сохранённые служебные атрибуты открытого PRT. Исходные даты выдачи, удалённые папки и их резерв, отменённые/незавершённые выдачи из утраченного Excel восстановить из текущего дерева нельзя. Если полную историю установить невозможно, для новых выдач назначьте заведомо неиспользованный диапазон. Дата новых строк — время восстановления.
