# Постпроцессирование и вывод на станок

Скрипт: [NX_Postprocess_To_Machine.cs](../scripts/NX_Postprocess_To_Machine.cs). [Все скрипты](../README.md#скрипты).

Выводит выбранные CAM-программы через назначенные постпроцессоры, сохраняет отдельные УП и при необходимости контейнер FANUCPRG.BIN.

## Изменения последней версии

**V1.40 · 07.10.2026**

- К номерам операций добавлены ведущие нули: до 99 операций включительно — `01_`, `02_`, … `99_`; если операций больше 99 — `001_`, `002_`, … уже с первой операции.
- Количество определяется отдельно для каждой выводимой УП до переименования. В режиме выбранных операций учитываются только выбранные операции этой УП. Повторный запуск заменяет старый номер и пересчитывает нужное количество знаков.
- Нумерация по-прежнему включается галочкой, снятой по умолчанию; её подсказка обновлена. Отмена, восстановление имён, пути, INI и прочие функции сохранены.
- Проверены компиляция C# 7.3 с моделями NX API, границы 9/10 и 99/100, 999 операций, независимый формат нескольких УП, повторная нумерация, выбранные операции, отмена и ошибки до сохранения результата. Запуск в целевой NX / Designcenter ещё требуется; автоматические проверки используют модели NX API.

## Выбор программ и постов

- Показывает папки в порядке дерева Program Order с вложенностью. Галочка родителя выбирает ветку; непосредственно выводятся программы с латинской заглавной O в начале имени.
- Вложенные O-программы выводятся отдельно, без повторного включения их операций в родительскую программу.
- Кнопка «Вывести УП для выбранных операций» использует только операции, выделенные в NX перед запуском. Для полученных программ можно задать O-номера.
- Можно выбрать общий пост для всех программ либо назначить свой пост каждой УП через «Разбить по разным постпроцессорам».
- Поиск поста работает по названию и пути. «Открыть INI» и «Обновить» позволяют изменить и перечитать конфигурацию.
- Список постов формируется из INI и, при соответствующей настройке, стандартного списка NX.

## Пути к постпроцессорам

В окне выбора поста нажмите «Пути к постпроцессорам». Настройка доступна и для общего поста, и при назначении поста каждой УП.

1. Нажмите «Добавить…» и выберите файл `.tcl` либо выберите существующую запись слева.
2. Задайте понятное название. Кнопки «Обзор…» позволяют выбрать TCL и DEF отдельно.
3. При выборе TCL одноимённый DEF из той же папки подставляется автоматически. Если такого файла нет, выберите DEF вручную.
4. Нажмите «Сохранить». Проверяются файлы и названия, изменения записываются в `NX_Postprocess_To_Machine.ini`, а список постов перечитывается.

Окно редактирует явные записи постов из INI. «Убрать» удаляет запись из настроек; файлы TCL и DEF остаются на месте. «Отмена» закрывает окно без записи. Прочие разделы, параметры, комментарии и кодировка существующего INI сохраняются. Если INI отсутствует, первое сохранение создаёт его рядом со скриптом. Для записи нужны права на эту папку.

## Папки со станками

В окне **«Куда вывести УП?»** нажмите **«Папки со станками…»**.

1. Нажмите «Добавить…», чтобы выбрать общую папку со станками. Поддерживаются локальные папки и сетевые пути вида `\\CNC-SERVER\Programs\Machines`.
2. Чтобы заменить уже настроенный путь, выберите запись слева и нажмите «Обзор…». Путь можно также вставить в поле вручную; кавычки команды Windows «Копировать как путь» поддерживаются.
3. При необходимости задайте название или добавьте другие общие папки. «Убрать» удаляет только запись из списка, сами папки и УП остаются на месте.
4. Нажмите «Сохранить». Путь и наличие пронумерованных подпапок проверяются, настройки записываются в `NX_Postprocess_To_Machine.ini`, а кнопки станков обновляются сразу.
5. Выберите станок и нажмите «Вывести», когда остальные параметры готовы.

Автоматически учитываются **только непосредственные подпапки с названиями из цифр**, например `01`, `02`, `15`. Вложенные уровни не просматриваются. При нескольких общих папках в подписях кнопок используется также название корня. Существующие отдельные записи из `[Machines]` продолжают отображаться; папки с произвольными именами можно добавить в этот раздел вручную.

«Отмена» закрывает настройки без записи и сохраняет текущее место вывода. После «Сохранить» место вывода нужно выбрать заново, чтобы УП не ушли в папку из прежнего списка. Сетевой каталог должен быть доступен текущему пользователю Windows; для сохранения настроек нужны права записи в INI, для вывода УП — в выбранную папку станка.

## Автоматическая нумерация операций

В первом окне выбора программ установите галочку **«Нумеровать операции»**, если нужно добавить номера. При каждом запуске она снята; выбор не записывается в INI. Без галочки сохраняются все текущие названия, в том числе уже имеющиеся номера.

При включённой галочке непосредственно перед постпроцессированием названия операций в дереве NX получают номера по порядку дерева Program Order. Каждая выводимая папка УП `O…` начинает собственную нумерацию заново. До 99 нумеруемых операций включительно используются префиксы `01_`, `02_`, … `99_`; если их больше 99 — `001_`, `002_`, … с первой операции. Названия самих папок и MCS не меняются.

Например, две операции в O100 получают имена `01_Черновая` и `02_Чистовая`. Если в O200 выводятся 100 операций, они нумеруются от `001_` до `100_`. Формат каждой УП выбирается независимо. Уже имеющийся начальный номер заменяется: повторный запуск не добавляет ещё один префикс. При изменении количества операций формат пересчитывается.

В режиме «Вывести УП для выбранных операций» нумеруются и учитываются при выборе формата только выбранные операции внутри каждой полученной УП; остальные операции сохраняют свои имена. При отмене или ошибке до сохранения первой УП возвращаются исходные названия. После успешного или частичного сохранения они остаются согласованными с результатом вывода; изменение можно отменить штатной командой NX. Для сохранения новых имён в проекте сохраните PRT обычным способом.

## Проверки перед выводом

- Сопоставляются диаметры, распознанные в названиях инструментов, с фактическими настройками инструментов всего CAM-проекта, включая неиспользуемые.
- Если найдены ошибки диаметров, белое окно с красным текстом показывает их список и вопрос «Продолжить?». Зелёная «Нет» останавливает выполнение; ярко-красная «Да» пропускает эту проверку для текущего запуска. По умолчанию выбрано «Нет».
- Проверяется MCS операций каждой выводимой программы. Смешанная или недоступная MCS показывается в отдельном предупреждении.
- При проблемах с диаметрами или MCS продолжение возможно только через явный выбор пользователя; настройки инструментов и MCS при этом не исправляются.
- Проверяются файлы постов, имена результатов, повторяющиеся пути, доступность папки и выбранного внешнего носителя.
- Все программы сначала подготавливаются и проверяются. Неожиданные дополнительные выходные файлы поста блокируют публикацию результатов.

## Параметры результата

- Выбор папки станка из INI, произвольной локальной или сетевой папки либо внешнего носителя. Поиск носителей выполняется по отдельной кнопке.
- Необязательное сохранение второй копии УП и BIN рядом с исходным PRT.
- Ручное назначение номера каждой УП: буква O добавляется автоматически, вводятся 1–8 цифр, номер 0 запрещён. Меняются имя файла и O-заголовок в коде; названия папок NX сохраняются.
- Расширение определяется назначенным постом и настройками конфигурации.
- Вывод начинается по кнопке «Вывести». Для замены существующих результатов требуется подтверждение.

## Вызов подпрограмм

В окне «Вызов подпрограмм» можно включить вызов остальных выбранных программ из первой и изменить порядок мышью или кнопками.

Главная УП последовательно вызывает остальные через M98 и завершается M30. Остальные УП завершаются M99. Для этого режима поддерживаются номера O1–O9999; формат вызова более длинных номеров зависит от стойки и здесь не выбирается автоматически.

## Обработка по нескольким привязкам

«Обработка по привязкам» задаёт список от одной до шести разных привязок: 1 = G54, …, 6 = G59. Их можно добавлять, удалять и переставлять. Для каждой выбранной УП обработка одного инструмента повторяется по всему списку, затем начинается следующий инструмент. MCS в NX не меняется.

Режим рассчитан на поддерживаемый трёхосевой числовой ISO-код с M06 и отводом G91 G28 Z0. Неподдерживаемые команды, макросы, выражения и неоднозначные состояния блокируют вывод пакета. Это не универсальное преобразование произвольной станочной программы.

## FANUCPRG.BIN

- BIN можно отключить, сохраняя только отдельные УП.
- «Добавить / обновить» сохраняет прочие программы существующего контейнера и заменяет совпавшие O-номера.
- «Новый BIN» создаёт контейнер только из выбранных УП.
- Выбирается ёмкость 2, 4, 8 МБ или свой размер. Полный размер файла показывается в окне; при переполнении автоматического увеличения нет.
- При нескольких местах сохранения каждый существующий BIN обрабатывается отдельно.

## Как пользоваться

1. Откройте CAM-проект с подготовленными траекториями. Если нужен вывод только части операций, выделите их до запуска.
2. В первом окне при необходимости установите «Нумеровать операции». Выберите программы или режим выбранных операций, проверьте сообщения о диаметрах и MCS.
3. Назначьте посты; при необходимости настройте TCL/DEF через «Пути к постпроцессорам». В окне места вывода при необходимости подключите общую папку через «Папки со станками…», затем выберите станок или другое место сохранения.
4. При необходимости задайте O-номера, BIN, вызовы подпрограмм, привязки и копию рядом с проектом.
5. Нажмите «Вывести»: при установленной галочке операции получат номера в дереве NX. Проверьте список заменяемых файлов и результат сохранения.

## Настройки и файлы

Основной INI — `NX_Postprocess_To_Machine.ini` рядом с журналом. Он содержит посты, папки станков, расширения и параметры вывода. Посты и общие папки станков можно настроить через интерфейс; отдельные записи станков и остальные параметры редактируются в INI. Относительные пути считаются от папки INI. Самих постпроцессоров в комплекте нет. Редакторы путей не создают дополнительные INI, резервные копии или отчёты.

Последняя ручная папка и выбор копии у проекта запоминаются в `%LOCALAPPDATA%\NX_Postprocess_To_Machine\LastChoice.ini`. Подготовка УП/BIN использует временную рабочую папку, которая удаляется при завершении. Постоянные резервные копии выходных УП и BIN не создаются. При сбое во время публикации часть результатов уже может быть сохранена; сообщение перечисляет такие файлы.

«Копия у проекта» означает копию выходных УП/BIN, а не сохранение самого PRT. Подробнее: [настройки постпроцессирования](configuration.md#постпроцессирование).
