# Установка и кнопки NX

**Русский** | [English](en/installation.md)

Целевые среды: Windows, NX 2506.8100 и Designcenter 2606 Build 4002. Скрипты выполняются внутри NX; NXOpen предоставляется установленной системой. Отдельный Python для запуска журналов не нужен.

## Первый запуск

1. Создайте папку для скриптов с правами записи текущего пользователя. По умолчанию используется `C:\ProgramData\NX_SCRIPTS`.
2. [Скачайте апдейтер](https://raw.githubusercontent.com/TonyFoxxxx/NXOpen-SCRIPTS/main/scripts/NX_Update_Scripts.py) и сохраните его в эту папку как `NX_Update_Scripts.py`. Сохраняйте исходный файл, без дополнительного расширения `.txt`.
3. В NX откройте **Инструменты → Журнал → Воспроизвести / Tools → Journal → Play**, выберите файл и запустите. Сочетание `Alt+F8` работает, если оно назначено в настройках NX.
4. В поле «Рабочая папка» укажите созданную папку. В поле «Источник» оставьте каталог:

```text
https://raw.githubusercontent.com/TonyFoxxxx/NXOpen-SCRIPTS/main/manifest.json
```

5. Нажмите **«Проверить»**. Апдейтер загрузит каталог и покажет доступные скрипты.
6. Отметьте нужные строки и нажмите **«Применить выбранное»**.
7. Перед использованием скриптов заполните их INI по [руководству по настройкам](configuration.md). Постпроцессированию нужны установленные посты и папки станков, нумератору — диапазон и XLSX-реестр, ЕСКД — совместимый внешний шрифт.

Если INI апдейтера отсутствует, «Проверить» создаёт его рядом со скриптом. Уже существующие INI при установке других скриптов сохраняются.

Для запуска установленного скрипта выберите его файл `.py` или `.cs` через Journal → Play. Для C#-журналов установка NX должна поддерживать их воспроизведение.

## Проверка апдейтера в NX

1. Запустите установленный апдейтер и нажмите «Проверить».
2. Убедитесь, что отображается каталог. Нажмите на строку: внизу появятся рабочий путь, источник и описание.
3. Для пробной установки можно выбрать `NX_Open_Project_Folder.cs`. Нажмите «Снять все», затем отметьте эту строку, если установка или обновление доступны.
4. Нажмите «Применить выбранное» и подтвердите показанные действия.
5. Повторите проверку. Ожидаемое состояние — «Установлена эта версия».
6. Откройте сохранённый PRT и запустите установленный `NX_Open_Project_Folder.cs`: должна открыться папка этого файла.

Если выбранный скрипт уже актуален, повторная установка не предлагается. Проверку установки можно пропустить или выполнить на другом отсутствующем скрипте. Объяснение состояний и условий выбора приведено в [руководстве апдейтера](updater.md#как-пользоваться).

При ошибке сначала проверьте её текст, указанный путь, доступность источника и права записи. Для обращения через [Issues](https://github.com/TonyFoxxxx/NXOpen-SCRIPTS/issues) укажите версии NX и апдейтера, шаги воспроизведения, текст ошибки и снимок окна с подробностями. Удалите из снимка и текста конфиденциальные пути и данные проекта.

## Кнопки

**Кнопка создаётся один раз для каждого скрипта на данном ПК и в используемой роли NX.** В ней хранится путь к локальному файлу. Апдейтер обновляет содержимое файла по этому пути, поэтому заново создавать кнопку после обновления не требуется.

1. Установите нужный скрипт в постоянную рабочую папку. Переключитесь в приложение NX, где будет нужна кнопка, например «Обработка», и выберите свою рабочую роль.
2. Нажмите правой кнопкой мыши на свободном месте ленты или панели инструментов и выберите **Настройка / Customize**. Также можно использовать `Ctrl+1`, если сочетание назначено в NX.
3. Откройте вкладку **Команды / Commands**. В категориях найдите **Новый элемент / New Item**; в некоторых версиях — **Новая кнопка / New Button**.
4. Перетащите **Новая пользовательская команда / New User Command** на нужную вкладку или панель. Дождитесь указателя места вставки и отпустите кнопку мыши.
5. Не закрывая Customize, нажмите правой кнопкой на новой кнопке и выберите **Изменить действие / Edit Action**.
6. В поле **Тип / Type** выберите запуск файла: **Execute an Action**; если есть отдельный тип для журналов — **Journal File**. Нажмите **Обзор / Browse** и выберите нужный `.py` или `.cs`. Если файл не виден, измените фильтр на нужное расширение или **Все файлы / All Files**.
7. Укажите полный локальный путь, например один из приведённых ниже. Подтвердите действие кнопкой **OK**.
8. В контекстном меню кнопки задайте понятное имя, например «Апдейтер скриптов» или «Карта наладки», и при необходимости измените значок. Название кнопки задаётся отдельно от текста всплывающей подсказки.
9. Закройте Customize и нажмите созданную кнопку. Должно открыться окно выбранного скрипта.
10. Сохраните текущую раскладку в пользовательской роли NX, если используете роли. При возврате к другой роли доступность кнопки определяется её настройками.

| Кнопка | Постоянный путь |
| --- | --- |
| Апдейтер скриптов | `C:\ProgramData\NX_SCRIPTS\NX_Update_Scripts.py` |
| Карта наладки | `C:\ProgramData\NX_SCRIPTS\NX_Setup_Prototype.py` |

Для остальных скриптов повторите настройку с их постоянными именами. Указывайте файл из рабочей папки, без номера версии в имени. Если используется другая папка, подставьте её полный путь.

При следующем обновлении запустите апдейтер, нажмите «Проверить», выберите обновления и примените их. **Апдейтер обновляет файлы внутри рабочей папки; пути и настройки кнопок остаются прежними.** Менять действие кнопки понадобится только при переносе или переименовании её файла.

Названия пунктов могут отличаться в зависимости от языка и версии NX. Описание настройки пользовательских команд: [NX Open User Guide, раздел Applications from a Toolbar Button](https://manualzz.com/doc/43946990/siemens-plm-software-nx-open-user-guide); пример интерфейса с Execute an Action: [инструкция JIVE Engineering](https://www.jiveengineering.com/nxblog/siemens-nx-custom-macro-journaling-tutorial).

## Ручная установка

1. Скачайте нужные исходники из [scripts/](../scripts) через Raw или в составе ZIP репозитория.
2. Скопируйте их в рабочую папку.
3. Для скриптов с настройками скопируйте соответствующий пример из [config/](../config), удалите `.example` из имени и заполните параметры. Если рабочий INI уже существует, сохраните его.
4. Запустите установленный файл через Journal → Play.

INI нумератора размещается в `C:\ProgramData\3_NX_DATA`. Пустой XLSX из [templates/](../templates) нужен только для первой установки. Если номера уже выдавались, используйте существующий реестр или восстановите его из резервной копии.

Папки `docs/`, `tools/`, `tests/` и manifest копировать в рабочую папку NX не требуется.

## Переход со старого имени апдейтера

С V1.13 апдейтер называется `NX_Update_Scripts.py`, его основной INI — `NX_Update_Scripts.ini`. Для V1.12 и более ранних версий нужен однократный ручной переход: старый апдейтер не распознаёт новое имя как собственное обновление. Каталог требует V1.13 и блокирует установку старым клиентом.

1. Закройте окно старого апдейтера.
2. Скачайте [актуальный NX_Update_Scripts.py](https://raw.githubusercontent.com/TonyFoxxxx/NXOpen-SCRIPTS/main/scripts/NX_Update_Scripts.py) в свою рабочую папку. Сохраните точное имя без добавления версии или `.txt`.
3. Переименуйте существующий `NX_Update_Script_Buttons.ini` в `NX_Update_Scripts.ini`, сохранив содержимое. Если целевой файл уже есть, сначала выберите INI с нужными рабочими настройками; не заменяйте его примером из GitHub.
4. Запустите новый `.py` через **Инструменты → Журнал → Воспроизвести / Tools → Journal → Play** и проверьте рабочую папку и источник. Старые `[Paths]` и `[Options]` поддерживаются; при отсутствии `[Source]` используется GitHub.
5. Если кнопка апдейтера уже создана, откройте **Customize → Edit Action** и один раз поменяйте её путь на новый `.py`. Кнопки остальных скриптов менять не требуется.
6. После проверки нового запуска уберите старый `.py` из рабочей папки. Нажмите «Проверить» в новом апдейтере; файлы без отметки происхождения могут потребовать индивидуального выбора.

Если основной INI пока отсутствует, новый апдейтер также умеет читать старый `NX_Update_Script_Buttons.ini` рядом со скриптом и сохраняет настройки в нём же, не создавая второй файл. При наличии обоих используется `NX_Update_Scripts.ini`.

**Этот переход выполняется один раз.** Последующие версии обновляют содержимое `NX_Update_Scripts.py` по тому же пути. Кнопка сохраняет своё действие.
