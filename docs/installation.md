# Установка и кнопки NX

Целевые среды: Windows, NX 2506.8100 и Designcenter 2606 Build 4002. Совместимость других сборок не заявляется.

## Первый запуск

1. Подготовьте `C:\ProgramData\2. NX_Scripts` с правами записи текущего пользователя. Если папка существует, используйте её.
2. Сохраните [Raw апдейтера](https://raw.githubusercontent.com/TonyFoxxxx/NXOpen-SCRIPTS/main/scripts/NX_Update_Script_Buttons.py) как `NX_Update_Script_Buttons.py`, без `.txt` и версии. HTML-страница GitHub не является скриптом.
3. Существующий INI не заменяйте примером. Если его нет, кнопка «Проверить» сохранит настройки; также можно скопировать example INI, убрав `.example`.
4. В NX откройте **Tools → Journal → Play / Инструменты → Журнал → Воспроизвести**, выберите `.py` и запустите. `Alt+F8` зависит от настройки горячих клавиш.
5. Проверьте рабочую папку и Raw URL источника. Нажмите «Проверить», выберите журналы и примените выбор.
6. Заполните INI перед работой. Не используйте пути из примера постпроцессирования. Нумератору нужны свой диапазон и история, ЕСКД — совместимый внешний шрифт.

Апдейтер использует стандартную библиотеку Python и Windows API; NXOpen предоставляется NX. Для `.cs` нужна возможность воспроизведения C#-журналов в вашей установленной NX. Заранее компилировать эти файлы не требуется.

## Переход с V1.08

V1.08 не читает GitHub manifest и исключает собственный файл из обновлений. Первый переход выполняется вручную при закрытом окне апдейтера:

1. Сохраните свой INI и собственные изменения исходников, если они есть.
2. Замените только рабочий `NX_Update_Script_Buttons.py` Raw-файлом V1.09.
3. Запустите его по тому же пути. `[Paths]` и `[Options]` будут прочитаны; при отсутствии `[Source]` включится GitHub. Старый `update_folder` остаётся для ручного режима папки.
4. При первой проверке локальные скрипты без служебной отметки могут потребовать ручного выбора обновления: их происхождение ещё не подтверждено.

Если кнопка указывает на имя с версией, один раз перенесите рабочую копию на постоянное имя и исправьте путь кнопки. Не оставляйте две версии одного журнала рядом: неоднозначная пара блокируется. Апдейтер сам не переименовывает существующие файлы и не редактирует команды NX.

## Кнопки

Существующая кнопка должна запускать журнал по абсолютному локальному пути, например `C:\ProgramData\2. NX_Scripts\NX_Setup_Prototype.py`. При обновлении путь не меняется. Raw URL в команде NX не нужен.

Новый журнал можно запускать через Journal → Play. Чтобы сделать отдельную кнопку:

1. Откройте **Customize / Настройка** интерфейса NX и раздел команд.
2. Создайте пользовательскую команду воспроизведения журнала и укажите полный путь к локальному `.py` или `.cs` в её действии.
3. Назначьте название и значок, разместите команду на панели или ленте.
4. Сохраните свою роль/настройку интерфейса и проверьте запуск.

Названия полей зависят от языка и роли NX. Используйте тот же тип действия, что у ваших работающих кнопок журналов. Апдейтер не создаёт New User Command и не меняет роль.

## Ручная установка

Скачайте нужные файлы `scripts/` через Raw или ZIP репозитория. Скопируйте журналы в рабочую папку. Примеры `config/` копируйте только при отсутствии личного INI и переименовывайте без `.example`.

INI нумератора размещается в `C:\ProgramData\3_NX_DATA`. Пустой XLSX нужен только при первоначальном создании истории. Если история уже была, используйте существующий реестр или восстановите его из своей резервной копии; не начинайте заново с пустого шаблона.

`docs/`, `tools/`, `tests/` и manifest в рабочую папку NX копировать не нужно. Журналы исполняются только по команде пользователя.
