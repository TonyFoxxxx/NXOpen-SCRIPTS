# Установка и кнопки NX

Целевые среды: Windows, NX 2506.8100 и Designcenter 2606 Build 4002. Скрипты выполняются внутри NX; NXOpen предоставляется установленной системой. Отдельный Python для запуска журналов не нужен.

## Первый запуск

1. Создайте папку для скриптов с правами записи текущего пользователя. По умолчанию используется `C:\ProgramData\NX_SCRIPTS`.
2. [Скачайте апдейтер](https://raw.githubusercontent.com/TonyFoxxxx/NXOpen-SCRIPTS/main/scripts/NX_Update_Script_Buttons.py) и сохраните его в эту папку как `NX_Update_Script_Buttons.py`. Сохраняйте исходный файл, без дополнительного расширения `.txt`.
3. В NX откройте **Инструменты → Журнал → Воспроизвести / Tools → Journal → Play**, выберите файл и запустите. Сочетание `Alt+F8` работает, если оно назначено в настройках NX.
4. В поле «Рабочая папка» укажите созданную папку. В поле «Источник» оставьте каталог:

```text
https://raw.githubusercontent.com/TonyFoxxxx/NXOpen-SCRIPTS/main/manifest.json
```

5. Нажмите **«Проверить»**. Апдейтер загрузит каталог и покажет доступные скрипты.
6. Отметьте нужные строки и нажмите **«Применить выбранное»**.
7. Перед использованием скриптов заполните их INI по [руководству по настройкам](configuration.md). Постпроцессированию нужны установленные посты и папки станков, нумератору — диапазон и XLSX-реестр, ЕСКД — совместимый внешний шрифт.

Если INI апдейтера отсутствует, «Проверить» создаёт его рядом со скриптом. Уже существующие INI при установке других скриптов сохраняются.

Для запуска установленного скрипта выберите его файл `.py` или `.cs` через Journal → Play. Для C#-журналов установка NX должна поддерживать их воспроизведение.

## Проверка апдейтера в NX

1. Запустите установленный апдейтер и нажмите «Проверить».
2. Убедитесь, что отображается каталог. Нажмите на строку: внизу появятся рабочий путь, источник и описание.
3. Для пробной установки можно выбрать `NX_Open_Project_Folder.cs`. Нажмите «Снять все», затем отметьте эту строку, если установка или обновление доступны.
4. Нажмите «Применить выбранное» и подтвердите показанные действия.
5. Повторите проверку. Ожидаемое состояние — «Установлена эта версия».
6. Откройте сохранённый PRT и запустите установленный `NX_Open_Project_Folder.cs`: должна открыться папка этого файла.

Если выбранный скрипт уже актуален, повторная установка не предлагается. Проверку установки можно пропустить или выполнить на другом отсутствующем скрипте. Объяснение состояний и условий выбора приведено в [руководстве апдейтера](updater.md#как-пользоваться).

При ошибке сначала проверьте её текст, указанный путь, доступность источника и права записи. Для обращения через [Issues](https://github.com/TonyFoxxxx/NXOpen-SCRIPTS/issues) укажите версии NX и апдейтера, шаги воспроизведения, текст ошибки и снимок окна с подробностями. Удалите из снимка и текста конфиденциальные пути и данные проекта.

## Кнопки

Кнопка должна запускать локальный файл по постоянному абсолютному пути, например `C:\ProgramData\NX_SCRIPTS\NX_Setup_Prototype.py`. При обновлении содержимого файла путь кнопки сохраняется.

1. Откройте **Customize / Настройка** интерфейса NX и раздел команд.
2. Создайте пользовательскую команду воспроизведения журнала и укажите полный путь к установленному `.py` или `.cs`.
3. Назначьте название и значок, разместите команду на панели или ленте.
4. Сохраните роль или настройки интерфейса и проверьте запуск.

Названия полей зависят от языка, версии и роли NX. Кнопки настраиваются вручную; апдейтер устанавливает и обновляет файлы.

## Ручная установка

1. Скачайте нужные исходники из [scripts/](../scripts) через Raw или в составе ZIP репозитория.
2. Скопируйте их в рабочую папку.
3. Для скриптов с настройками скопируйте соответствующий пример из [config/](../config), удалите `.example` из имени и заполните параметры. Если рабочий INI уже существует, сохраните его.
4. Запустите установленный файл через Journal → Play.

INI нумератора размещается в `C:\ProgramData\3_NX_DATA`. Пустой XLSX из [templates/](../templates) нужен только для первой установки. Если номера уже выдавались, используйте существующий реестр или восстановите его из резервной копии.

Папки `docs/`, `tools/`, `tests/` и manifest копировать в рабочую папку NX не требуется.

## Переход с V1.08 или V1.09

В этих версиях нужен однократный ручной переход: V1.08 не поддерживает каталог GitHub, а V1.09 содержит ошибку замены существующих файлов на Windows.

1. Закройте окно апдейтера и сохраните рабочий INI.
2. Замените только `NX_Update_Script_Buttons.py` файлом по ссылке из раздела «Первый запуск».
3. Запустите его по прежнему пути. Старые `[Paths]` и `[Options]` будут прочитаны; при отсутствии `[Source]` включится GitHub. Поле `update_folder` используется для режима папки.
4. Проверьте список. Файлы без служебной отметки происхождения могут потребовать индивидуального ручного выбора.

Если кнопка ссылается на файл с версией в имени, перенесите рабочую копию на постоянное имя и один раз обновите путь кнопки. Две копии одного скрипта в рабочей папке блокируют неоднозначное обновление.
