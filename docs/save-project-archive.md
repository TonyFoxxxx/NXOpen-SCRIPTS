# Сохранение проекта и архива

**Русский** | [English](en/save-project-archive.md)

Скрипт: [`NX_Save_Project_And_Archive.py`](../scripts/NX_Save_Project_And_Archive.py). Версия: **V1**.

## Изменения последней версии

**V1 · 11.11.2026** — первый выпуск.

- Штатное сохранение рабочей детали с проверкой ошибок NX, без изменения пути и без закрытия проекта.
- Один ZIP рядом с проектом; повторный запуск заменяет его содержимое последней сохранённой версией `.prt`.
- ZIP собирается и проверяется в памяти. После записи проверяются CRC, размер и SHA-256 распакованного `.prt`.
- При перехватываемой ошибке записи скрипт пытается восстановить прежний ZIP из памяти и проверяет восстановление. О результатах сохранения проекта и архива сообщается отдельно.

## Порядок работы

1. Один раз сохраните проект обычной командой NX в файл `.prt`.
2. Сделайте нужный проект **рабочей деталью (Work Part)**. Если рабочей деталью назначен компонент сборки, сохраняется и архивируется именно он.
3. Воспроизведите журнал или запустите его своей кнопкой. В апдейтере пункт называется **«Сохранение проекта и архива»**.
4. NX сохраняет рабочую деталь и её изменённые компоненты через `BasePart.Save(SaveComponents.TrueValue, CloseAfterSave.FalseValue)`.
5. Если NX не сообщил о несохранённых деталях/объектах и рабочая деталь больше не отмечена изменённой, скрипт читает сохранённый основной `.prt` и обновляет ZIP.
6. Появляется результат. После закрытия сообщения можно продолжать работу и пользоваться обычным сохранением.

Например, рядом с `Деталь.prt` появляется `Деталь.zip`, внутри которого находится один файл `Деталь.prt`. Даты и номера версий в имя не добавляются. При уменьшении проекта старый ZIP также уменьшается; старые записи внутри архива не накапливаются.

**Внешние компоненты сборки в ZIP не входят.** Изменённые компоненты сохраняет штатная команда NX, но архив содержит только рабочий `.prt`. Это не пакет полной сборки и не архив всей папки: чертежи из отдельных файлов, карты наладки, УП, изображения и другие файлы не добавляются.

## Обычное сохранение после скрипта

Скрипт не вызывает `SaveAs`, не переименовывает `.prt`, не заменяет его копией на уровне файловой системы, не переключает Work/Display Part и не создаёт точки отмены или обработчики сохранения. Исходный файл открывается скриптом только для чтения после завершения штатного сохранения. Все файловые дескрипторы и `PartSaveStatus` освобождаются до сообщения о результате.

Обычное сохранение обновляет исходный `.prt`. ZIP обновляется только при запуске этого журнала.

## Создаваемые файлы и настройки

- Единственный дополнительный файл самого скрипта — `<имя проекта>.zip` в папке `.prt`.
- Нет INI, служебных файлов, журналов, резервных ZIP, подпапок или временных файлов, в том числе в Temp. Метка принадлежности архиву хранится в комментарии самого ZIP.
- Скрипт не изменяет настройки NX, глобальные пути, правила резервного копирования или автосохранения. Собственные служебные файлы NX определяются настройками самого NX; скрипт их не создаёт дополнительно и не удаляет.
- Существующий одноимённый ZIP другого происхождения, ZIP с добавленными посторонними файлами или нераспознаваемый ZIP не перезаписывается. Скрипт сообщает о конфликте.
- Ссылки/перенаправления и архивы с несколькими жёсткими ссылками не используются для записи.

## Ошибки и ограничения

- Если сохранение NX не подтверждено, ZIP не изменяется. Скрипт не может устранить неисправности сохранения самого NX, сетевого диска или сторонних обработчиков.
- Если NX сохранил проект, но архивирование не удалось, результат прямо говорит **«Проект сохранён штатной командой NX»** и отдельно описывает ошибку ZIP. Проект не откатывается.
- Новый ZIP полностью формируется в оперативной памяти. При замене там же удерживается прежний ZIP. Недостаток памяти до записи не повреждает прежний архив.
- Во время записи ZIP закрыт для параллельного доступа. Блокировки снимаются при завершении или обработанной ошибке. Одновременное редактирование одного `.prt` разными сессиями NX этим скриптом не координируется.
- **Без временного файла замена ZIP не является атомарной.** Отключение питания, принудительное завершение процесса или потеря доступа к диску прямо во время перезаписи могут повредить архив. Восстановление из памяти возможно только при ошибке, которую работающий процесс смог обработать. Само архивирование не перезаписывает исходный `.prt`.
- Новый ещё не сохранённый проект, Teamcenter-путь и проект только для чтения требуют штатных действий пользователя до запуска журнала. Цель — обычные `.prt` на файловой системе Windows; сетевые пути зависят от доступности и прав сервера.

## Проверки

Проверены файловые сценарии создания и замены ZIP, отсутствие дополнительных файлов, освобождение блокировок, обычная запись `.prt` между двумя запусками, ошибки NX, нехватка памяти, частичная запись, восстановление и конфликт существующего архива. Использованные свойства и методы сверены с установленными Python stubs и заголовками NX Open Designcenter 2606.

Непосредственная проверка в установленном **Designcenter 2606** на отдельном тестовом `.prt` прошла: скрипт → изменение модели и штатный Save → изменение модели и повторный запуск скрипта. Исходный путь, Work Part и Display Part сохранились. ZIP содержит ровно один `.prt`, побайтово совпадающий с последним сохранённым оригиналом. В папке проекта остались только `.prt` и `.zip`. 22 специализированных автоматических теста прошли. Проверка на производственной сборке и сетевом сервере не выполнялась.

Общий набор репозитория: 313 тестов, при первом запуске один сбой прежнего теста нумератора и один сетевой сбой теста карты наладки. Все 10 тестов сохранения карты наладки прошли при отдельном повторе. Прежний тест нумератора повторно завершился кодом 5 без сообщения; его исходник и тест не менялись этим выпуском. Проверка каталога, версий и SHA-256 прошла.
